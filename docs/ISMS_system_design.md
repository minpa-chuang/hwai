# ISMS 資訊資產盤點與風險管理系統設計

本文件彙整系統的主要模組、技術選型及資料流等設計要點，供後續開發參考。

## 1. 目標
建立可視化且高效的資訊資產與風險管理平台，支援年度資料複製、風險再評鑑與多樣化報表，符合 ISO 27001 等 ISMS 標準。

## 2. 系統模組
1. **資訊資產管理**：
   - 資產登錄、編輯、盤點紀錄與生命週期管理。
   - 多維度分類與搜尋，支援文件上傳與備註。
2. **風險評估與再評鑑**：
   - 威脅/漏洞庫與風險矩陣設定。
   - 風險識別、分析、處理與再評鑑流程。
   - 具備年度匯入機制，新年度資料標記為「待再評鑑」。
3. **報表與儀表板**：
   - 資產清單、風險報告、趨勢分析等報表，可輸出 PDF/Excel。
   - 互動式儀表板與下鑽功能，呈現資產分布、風險等級與處理進度。
4. **權限與用戶管理**：
   - 系統管理員、資產管理者、風險評估員、只讀使用者等角色。
   - 支援細粒度權限控制與帳號管理。

## 3. 技術架構
- **前端**：建議使用 React (或 Vue.js) 搭配 ECharts/Chart.js 進行可視化開發。
- **後端**：PHP Laravel 框架，提供 RESTful API 與資料驗證。
- **資料庫**：MySQL，依年度分區儲存資產與風險資訊。
- **報表**：Dompdf 產生 PDF，PhpSpreadsheet 產生 Excel。
- **部署**：Ubuntu 伺服器，Nginx 或 Apache 搭配 PHP-FPM。

## 4. 資料流程概述
1. 使用者於前端登錄或更新資產資訊，資料透過 API 儲存至 MySQL。
2. 風險評估模組提供威脅/漏洞選擇與評分，計算風險值與殘餘風險。
3. 報表模組根據資料庫資料產出圖表與文件，可定期排程寄送。
4. 年度切換時，系統可複製上年度資料作為新年度基準，並標記為待再評鑑。
